# GUI テーマ刷新設計書（インテリジェンス製品風ダークテーマ）

- 作成日: 2026-10-17
- 対象: `serve` の Web GUI（`internal/web/page.html`）
- ブランチ: `feature/overview-polish`（作業中のスクロール修正を含む）
- 確認済みモックアップ: `.superpowers/brainstorm/1075-1792228074/content/intel-theme.html` の B 案

## 1. 目的と背景

PR #14 で Overview タブ（全 Finding の判定フロー図と一覧）を追加した。その後、利用者から次の2点の指摘を受けた。

1. スクロールできる範囲が画面の下半分だけで、見づらい。
2. フロー図の色使いが野暮ったい。さらに、フロー図だけでなく GUI 全体を「脅威インテリジェンス製品らしい」デザインにしたい。

参考として挙がったのは、Recorded Future（https://www.recordedfuture.com/jp/）の製品ダッシュボード画面と、Filigran OpenCTI（https://filigran.io/ja/products/opencti）。共通する特徴は、濃紺から黒の背景、1px の細い線で区切ったカード、情報量の多い業務用ダッシュボード。OpenCTI はこれに、青からシアンへのグラデーションと発光を差し色として加えている。利用者は OpenCTI 寄りの「B 案（青→シアン）」を選んだ。途中でニューモフィズムも検討したが、参考サイトの方向性と合わないため採用しない。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
1. **スクロール**: デスクトップ幅（1001px 以上）では、右側の判定列全体を1つのスクロール領域にする。結果タブは上部に貼り付ける（sticky）。700px 以下と 1000px 以下の既存の挙動（ページ全体のスクロール）は維持する。
2. **テーマ**: GUI 全体（ランディング、トップバー、KPI 帯、サイドバー、結果パネル、タブ、表、フロー図、1件ツリー、ダイアログ、フォーム、トースト）を新しいトークンで統一する。
3. **フロー図**: C 案の配色にする。箱は塗りつぶさず細い枠線だけにし、結果の箱は「その結果の色の枠線と、薄い同色の塗り」にする。帯は結果の色で `fill-opacity` 約 .3、`mix-blend-mode: screen` で重ねて、重なっても濁らないようにする。
4. **結果ヘッダー**: パネル上端に、最も緊急度の高い結果の色で 2px の線を引く。Overview タブの先頭に、4つの結果ごとの件数を左端の色線付きで並べる（モックアップの `.kp`）。
5. **オフライン動作の維持**: 外部 CDN やフォントサービスに依存しない。

### 非ゴール
- HTML レポート（`internal/report`）と CLI 出力の見た目は変えない。
- 画面の情報構成と操作（タブの種類、API、JS の状態管理）は変えない。見た目だけを変える。
- ライトテーマ（白背景）は作らない。今もダークのみで運用している。

### アンチゴール（動いても失敗とみなすもの）
- 結果の4色が区別しにくくなる（特に Scheduled の青と、差し色のシアンが紛らわしくなる）。
- 本文や数字のコントラストが WCAG AA（通常文字 4.5:1）を下回る。
- 既存の操作（ターゲット追加、アップロード、実行、SSVC 入力レビュー、フィルタ、詳細へのジャンプ）やキーボード操作が壊れる。
- オフライン環境でフォントが崩れる、または外部へ通信する。

## 3. デザイントークン（B 案）

| 役割 | 値 |
|---|---|
| 背景 `--bg` | `#060a13` |
| 面1 `--s1`（パネル、サイドバー） | `#0b1222` |
| 面2 `--s2`（ホバー、入力欄） | `#101a2f` |
| 線 `--line` / 強い線 `--line2` | `#1b2740` / `#26344f` |
| 文字 `--ink` / 補助 `--mut` / 弱 `--dim` | `#e4eaf6` / `#8391ab` / `#56637c` |
| 差し色 `--acc` / `--acc2` | `#22d3ee`（シアン）/ `#3b82f6`（青）。主要ボタンとロゴは `linear-gradient(90deg, #3b82f6, #22d3ee)` |
| 発光 `--glow` | `0 0 0 1px #22d3ee66, 0 0 20px #22d3ee33`（選択中のターゲット、フォーカスに限って使う） |
| 結果の色 | Immediate `#ff5a5f`、Out-of-Cycle `#ffb340`、Scheduled `#5b8cff`、Defer `#64748b` |

- **差し色の使い分け**: シアンは「操作できるもの・選択状態」（リンク、タブ下線、選択枠、フォーカス、主要ボタン）だけに使う。結果の色は「判定結果」だけに使う。両者を混ぜない。
- **書体**: IBM Plex Sans（400/500/600）を本文と見出しに使う。IBM Plex Mono（400/500）は CVE 番号とハッシュだけに使う。数字は `font-variant-numeric: tabular-nums` で桁をそろえる。
- **角丸**: パネルは 8px、カードと入力欄は 6px、バッジは 4–5px。用途ごとに使い分け、すべて同じ値にはしない。
- **影**: 黒い影は使わない。奥行きは「面の明度差」と「細い線」で表す。発光は前述の箇所に限定する。

## 4. 実装方針（決定事項）

- **CSS の構成**: `page.html` には、古いライトテーマの `<style>`（6行目〜）と、それを上書きする `<style id="console-theme">`（226行目〜）が積み重なっている。`console-theme` ブロックを新しいテーマブロックに**置き換え**、トークンは `:root` の CSS 変数で定義する。古いブロックのうち、レイアウト（グリッド、レスポンシブ）は残し、色と影の指定だけを新しいブロックで上書きする。
- **JS 側の色**: `OUTCOME_COLOR` は CSS 変数（`--c-immediate` など）を参照する作りのまま、変数の値だけ新しい色にする。`treeSvg` / `flowSvg` の中で直書きされている色は、クラスと CSS に移す。
- **フォントの同梱**: IBM Plex Sans / Mono（SIL Open Font License 1.1）の Latin サブセット woff2 を `internal/web/fonts/` に置き、`go:embed` でバイナリに含めて `/fonts/...` から配信する。ライセンス文も同梱する。サイズの増加は合計 150KB 程度を見込む。
- **スクロール**: 作業中の修正（`@media(min-width:1001px)` で `.decisionpane` をスクロール領域にし、`.resulttabs` を sticky にする）をこの作業に含める。

## 5. 検証

- `go vet ./...` と `go test -count=1 ./...` が通ること。フォント配信のテスト（Content-Type と 200 応答）を追加する。
- Playwright でオフラインデモを実行し、1440px / 1000px / 390px の各幅でスクリーンショットを撮って目視確認する。確認する画面は、ランディング、ワークスペース、各タブ、ダイアログ。
- 確認項目: コンソールエラーがない、ページ全体が横にはみ出さない、デスクトップで判定列全体がスクロールしタブが上に貼り付く、フィルタと詳細へのジャンプが動く、外部への通信が発生しない（Playwright でリクエストを監視する）。
- 主要な文字色と背景色の組み合わせについて、コントラスト比を計算で確認する。

## 6. 実装者の判断に任せる部分

- ランディングページのヒーロー部分の細かい構成（今の文言と要素は維持したうえで、新しいトークンで整える）。
- ホバーやフォーカスの細かい表現、余白の微調整。
- フォントのサブセット化の方法（`pyftsubset` などのツールは問わない）。
